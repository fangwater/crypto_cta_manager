# el01 策略创建者权限修复，2026-10-15

shaokai 新建的 10 个私有策略均正确保存了 `created_by_user_id`，但
`PositionAccess` 和目录过滤使用的 `PositionVisibility` 都没有把创建者
纳入 `user_can_configure`。本人可查看和更新目标，却看不到权限管理中的
策略，也不能用它新建账户绑定。发布前生产接口确认：本人 10 个策略可编辑，
其中 0 个出现在可配置策略列表。这是权限模型遗漏，与内存无关。

创建者现在与推送管理者一样自动拥有自己策略的配置权限，可以管理策略的
用户授权。替换显式授权列表不会移除创建者的固有权限；普通配置被授权者仍
不能通过替换列表移除自身权限。目录过滤、写接口、绑定和 Virtual 引用共用
这个判断。账户绑定继续要求目标账户独立的配置权限。仅查看、公开可见或
知道策略名都不会获得配置权限；管理员专有的全员可见、推送 token 和推送
管理者设置保留原规则。

权限页把创建者、推送管理者显示为“自动可配置”，禁用该行无法实际降权的
按钮。普通用户的页面说明同步更新，不再声称新建策略只能由管理员执行。
现有策略根据已记录的创建者直接生效，无需修改所有者、补授权或运行 DDL。

本地验证包括 `cargo fmt --check`、`cargo check --locked`、
`cargo test --locked`、`cargo build --locked --release --bin cta_web`，
以及前端 build / lint。新增回归覆盖创建者无显式授权、冗余 view 授权、
