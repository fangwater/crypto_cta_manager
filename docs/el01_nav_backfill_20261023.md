# el01 分钟估值回填阻塞修复 — 2026-10-23

操作员报告 `binance_exec_trade04` 的 1D 净值持续显示
“实际持仓的分钟估值价正在后台补齐，完成后自动重算”。通过 el01 原有 Nginx
网关复现 HTTP 503，`loading=true`。只读检查 Manager `klines_1m` 发现该账户
12 个币种的最后收盘时间落在 UTC 00:45–01:04，而诊断已接近 UTC 06:00。
当时存在约 135–173 个回填，行情预算为 120 weight/minute。

## 原因与修复

每次自动重试都会启动新的 detached 回填。同一币种的任务在 mutex 后排队，
过时的结束时间不断积累；一个长历史任务又会一直持锁，阻塞新一分钟的查询。
HTTP 并发许可在等待权重前取得，进一步让历史请求占住全部许可。

现在每个币种只有一个共享回填任务，重试合并范围。范围扩展会中断旧 pass，
从最新缺口恢复；24 小时块和块内缺失页均从新到旧获取。已经保存的分钟继续
复用，缺失分钟不做负缓存。HTTP 许可与滚动分钟权重一起分配，按 candle end
优先处理较新的数据，相同结束时间按等待顺序处理。取消请求会释放队列项与
许可；取消浏览器等待不会终止共享回填。完整缓存查询仍绕过历史回填。

没有修改 FIFO、成交价格、手续费、分钟收盘估值、账户/策略归因或缺价时拒绝
部分曲线的规则。回填只处理分析所需的币种与时间范围，保留原有五个默认币种。

第一轮只合并任务的修复已在固定窗口恢复，但后续新分钟仍被长历史 pass 阻塞。
操作员反馈后补齐中断、从新到旧取页和 HTTP 额度调度；最终验收包含连续新分钟，
不将第一轮固定窗口的成功视为完成。

## 非交易出口与预算

操作员明确授权提高独立非交易 IP 的权重。核对 14 份交易引擎 IP 配置，并用
不发送数据包的路由选择确认 `0.0.0.0` 实际解析到 `154.197.32.6`。
`154.197.32.9`、`154.197.32.10` 均绑定在 `ens18`，分别绑定 socket 后通过
公网出口核验。Kline 继续固定使用 `.10`，保留原 IP 排除项，不引入多 IP 池。

通过 `.10` 读取 Binance USD-M `exchangeInfo`，返回的 REQUEST_WEIGHT 上限为
2400/minute。el01 的 `kline.weight_per_minute` 从 120 提到 **1200**，HTTP
并发保持 **8**。配置结构逐项比较确认只有该权重变化。保留 429/418 的全局
Retry-After 冷却与禁止代理、默认路由回退的规则。其他主机没有部署或配置变更。
