# jp-meta 理财与 BNB 出口预算调整（2026-10-30）

操作员同意将 USD-M 的单出口保守阈值从 1200 调至 1800 weight/min，
并让每轮优先选择可用额度更多的既有交易出口。一轮内固定 IP；不改变交易
进程的绑定，不将未知结果的资金请求换 IP 重发。

## 出口与预算

发布前通过两个账户的实时 `trade_engine.toml` 及显式绑定的公网查询确认：

| 本地地址 | 公网出口 | 04:23:48 UTC 的 USD-M 已用权重 |
| --- | --- | ---: |
| 172.31.35.228 | 13.115.227.29 | 1217 |
| 172.31.35.234 | 54.64.228.233 | 16 |

两条出口的 Binance `/fapi/v1/exchangeInfo` 均返回 `REQUEST_WEIGHT` 上限
2400/min。Manager 的 1800 阈值包含响应头所反映的其他进程用量，给交易所
上限留下 600 余量，并非 Manager 独占 1800。不能把两个 IP 的余量用于一条
出口，也不能因两个 IP 而增加账号的 UID 限额。

Spot/SAPI-IP 的 4500、SAPI 账号操作的保守 6000 阈值及接口权重均不变。
Kline 继续使用独立 `.93` 出口及 600/min 配置，未借用它的额度。

## 实现

- 共享限流器公开只读容量快照；选择不预占额度，每个实际请求仍单独预留。
- 比较候选出口的 USD-M、Spot、SAPI-IP 剩余比例，按其中最小比例择优；
  跳过额度不足或正在冷却的出口。同分时使用原有共享轮换游标。
- 使用已有响应头和本地预留，不额外发 REST 探测请求。未观察或已过期的
  出口没有已知占用；首次响应会校正额度，后续请求仍受预算和冷却约束。
- 每条用量响应各保留 60 秒，同时计入该响应之后的本地预留。旧实现将
  `max(旧高水位, 新响应)` 的时间反复刷新，可能让较低响应延长旧高水位；
  现在各自到期，仍不会因乱序响应而提前丢弃尚未到期的高用量。
- 记录候选容量和所选 IP；预算拒绝记录接口、额度池、已用值、请求权重、
  报价接受预留及阈值。
