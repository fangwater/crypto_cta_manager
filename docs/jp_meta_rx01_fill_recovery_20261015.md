## 读取修复

部分订单在 `uniform_orders` 中只有零成交生命周期记录，或只有部分成交；
完整事实已在 `rapidx_executions`。原恢复逻辑只处理数量大于零、价格缺失
的记录，因此漏掉这些有真实价格和数量的成交。

现在对 RapidX 外部订单按 source、portfolio、exchange、symbol、venue 和
client order ID 关联证据。检查存储身份散列、方向、交易所订单 ID 和订单
创建时间；WS/REST 按 transaction ID 去重。只恢复已有本源订单身份的
成交，不纳入无关联的历史账户成交，也不替换内部交叉成交。

当事实成交数量高于生命周期累计数量时，分析投影使用去重后的完整事实。
证据尚未覆盖已定价生命周期数量时继续保留原记录；缺价成交仍要求完整
证据。记录时间和策略归属来自原始订单，成交价格、数量和时间来自事实。
Maker/Taker 及未知角色沿用既有费用解析，未引入新的费率假设。

增量缓存保留原始生命周期，之后每次刷新核对成交证据，即使没有新增
`uniform_orders` 也能补入晚到事实。正式回报随后补齐时重新比较投影，
不会在恢复成交之上再次叠加；重复刷新不变更 FIFO generation。
原 Exec RocksDB 全程只读。

| 永续数量全部一致 | 否 | 是 |
| 扣估算手续费 NAV 变化，报价币 | 93.93 | -166.28 |

NAV 是订单 FIFO 结果，以最新成交价标记持仓，不代表交易所账户权益。
现货余额扣币、借币利息等账务运动未包含；表中的估值仅用于衡量数量
误差，不是这些账务项的精确费用计量。实盘持续成交，以上为固定观察
窗口的读数。

验证期间曾遇到一笔 ADA 永续实际回报先到、持久化证据后到的短暂差异；
后续稳定窗口全部永续对齐。该异步时间差不通过修改接管快照掩盖。
