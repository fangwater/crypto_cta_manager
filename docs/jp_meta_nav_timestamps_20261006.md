## 时间戳规则

API 请求的 `startMs`、`endMs` 是 Unix 毫秒，内部订单、信号和净值点
使用 Unix 微秒。前端绘图统一做一次 `ts_us / 1000`，实际与理论各自
携带横轴时间戳，不按点数组下标配对。日期输入和图表显示均使用浏览器
本地时区；本次浏览器核查设置为 Asia/Shanghai，确认北京时间输入能
往返成相同的 Unix 毫秒。

实际成交按 `uniform_orders.update_ts_us` 排序和入账，RocksDB 接收键仅
作稳定排序依据；旧记录缺少有效 update 时间才使用接收键的时间。理论
目标按 Manager 归档接收/发布时间安排五个完整分钟，跳过部分到达分钟。
每个虚拟成交点记在其分钟收盘边界，估值只使用该点之前已经收盘的行情。
从请求起点前重建库存并以起点已收盘价格设零费用基准；起点时刻的成交
仍属于区间。

trade04 抽查示例（北京时间）：

| 事件 | 时间 |
| --- | --- |
| `rbf_big` / `UNIUSDT` 目标归档 | 10-06 11:45:03.117 |
| 五根 K 线开盘 | 11:46、11:47、11:48、11:49、11:50 |
| 五笔虚拟成交/收盘时间 | 11:47、11:48、11:49、11:50、11:51 |
| 理论执行窗口完成 | 11:51 |

实时理论曲线需要知道完整五分钟的有效成交分钟数，因此最多显示到当前
最新已收盘分钟之前四分钟。本次实际终点为 12:07:13，理论终点为
12:03:00，约早 253 秒；这是完整窗口等待规则。
