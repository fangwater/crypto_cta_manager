# el01 理论 FIFO 汇总估值优化（2026-11-12）

操作者要求继续降低 7D 理论净值的首查耗时，并明确先优化算法和数据结构，
不增加多线程。上一版固定 `binance_exec_trade06` 7D 请求为 9.041 秒，其中
FIFO 曲线计算 6.994 秒、理论定价 225 ms、分钟行情扫描 122 ms。该窗口有
81,765 个目标增量、408,825 个虚拟成交和 95 个市场，行情覆盖完整。

本次保留各 source/symbol/venue 的独立 `VecDeque` FIFO。每次新增、部分平仓、
移除批次时，维护数量与开仓成本偏移的补偿和。设账本首次开仓价格为 `a`，
估值使用 `Q * (mark - a) - Σ(q * (entry - a))`，避免直接相减两个大额报价
名义本金。完全平仓时清空汇总；同一笔成交反手后以新开仓价重新取锚点。
旧、新批次数量分别移除和加入，以 FIFO 实际存储的舍入数量为准。

逐笔持仓数量核对及浮盈估值从扫描全部未平仓批次变为常数时间。平仓仍按原 FIFO
顺序逐批匹配，已实现盈亏和手续费沿用原运算顺序。总工作量从约
`O(成交数 × 批次数 + 估值时点数 × 账本数 × 批次数)` 降为
`O(成交数 + 实际关闭批次数 + 估值时点数 × 账本数)`。
理论成交价格由树查找改为连续数组按目标增量索引访问。

没有增加或重配线程。原有并行分钟定价、分析线程池和 CPU 绑定保持现状，FIFO
重放与汇总仍在单线程执行。不增加持久化缓存，不改变行情出口、请求预算、协议、
费用设置、资金费算法或数据库 schema。

单线程 release 基准：同价附近持续开仓至 40,000 个 FIFO 批次，每次成交及估值
执行相同工作，扫描版 2,244 ms，汇总版 5 ms。结果保留相同批次和顺序，已实现
盈亏与手续费相同。该合成场景用于检验随批次累积的复杂度，不代表整条线上 API。
