# RapidX 三分钟 VWAP 与 TWAP 双参考

2026-10-22 按操作员要求，RapidX 系列同时提供「理论3min_vwap」和「理论3min_twap」两个参考；
其他账户保持原有五分钟理论 TWAP。此变更作用于理论 NAV 和持仓成本分析。

账户识别使用 source 对应 Exec 环境中的 `TRADE_ENGINE_EXEC_BACKEND` 和
`TRADE_ENGINE_EXEC_BACKEND_MAP`，沿用现有后端解析与交易所映射优先级。
`rapidx` / `ltp` 等既有别名都识别为 RapidX；账户显示名、RX01 等标签不参与判断。
显式配置文件缺失或后端配置无效时返回错误，不静默切换算法。

设 `t` 为目标发布时间向上对齐的首个完整分钟。正好在整分钟发布时从该分钟开始；
分钟内发布则从下一分钟开始。RapidX 使用 `[t,t+180s)` 的三根已收盘 1m K 线：

```text
理论3min_twap = (A0/V0 + A1/V1 + A2/V2) / 3
TWAP 第 i 分钟理论数量 = delta / 3
理论3min_vwap = (A0 + A1 + A2) / (V0 + V1 + V2)
第 i 分钟理论数量 = delta × Vi / (V0 + V1 + V2)
第 i 分钟理论成交价 = Ai / Vi（Vi > 0）
```

`Ai` 为市场成交额，`Vi` 为市场成交币数量，不区分买卖方向；订单 delta 的正负
仅控制理论执行方向。分钟切片在各分钟收盘时应用，因此完整窗口的数量加权均价
恰好等于上述合并 VWAP。后续目标仍有独立窗口，不截断此前窗口。

VWAP 有完整 K 线但单分钟零成交时，该分钟权重为零。TWAP 要求三个分钟均有成交，
否则分钟均价无法计算，返回明确不可用，不跳过分钟、不用收盘价替代。三分钟全部零成交时 VWAP 无定义，
返回明确不可用；不改用收盘价。任一分钟缺失时保留缺口并等待既有缓存补齐，
不返回部分定价的理论曲线。完整窗口才能确定每分钟权重，最新 RapidX 曲线最多
到当前已完成分钟边界之前两分钟；其他账户继续延后四分钟。

五分钟 TWAP 保持原算法：有成交的 N 个分钟各执行 delta/N，均价为各分钟 VWAP
的算术平均；五分钟全部无成交时才使用五根收盘价。实际订单价格、数量、费用、
FIFO、资金费、归档目标/份数/费率均不改变。持仓成本仍按真实成交数量比较价格和
费用，订单信号与目标之间原有 300 秒匹配上限也不改变。

理论 NAV 继续使用已完成分钟收盘价估值，保留窗口起点零基线、起点成交归入区间、
跨窗口初始库存零费用，以及 source/symbol/venue 隔离。三分钟模型和五分钟模型
共享原始 K 线缓存，派生价格及曲线缓存包含执行模型，避免互相复用错误的结果。
仅使用已有行情覆盖；尚未接入的 venue 不会因识别为 RapidX 就获得模拟价格。

API 使用同一个现行契约：净值的 `theoretical` 和 `execution_slippage` 按相同顺序
返回参考数组；成本的 `reports` 返回各参考的完整汇总和明细。RapidX 两个参考，
其他账户一个。`execution_model` 为 `vwap3m`、`twap3m` 或 `twap5m`，
`execution_window_secs` 为 180 或 300。跨模型合并查询的 model 为 null，窗口
长度取所选账户最大值；先返回事实数据、尚未计算理论时 model 也为 null。
浏览器仍按既有规则只查询一个账户。成本行返回三个或
五个 `sample_prices` 及对应 `sample_quantity_weights`，另有 `reference_prices`
同时列出各参考价格。净值曲线及成本复盘价格图同时展示两套三分钟参考，
成本页可选择参考查看对应滑点、费用及明细。页面据此调整标题、
窗口阴影和价格形态分析。前后端需要一同发布。

成本 API 原有 `five_sample_drift_usdt` 字段保留名称，仍表示首个计价分钟相对
窗口理论均价的方向调整价差金额；RapidX 时对应三分钟窗口，前端使用“窗口理论
均价”说明该分解。

回归覆盖后端映射优先级、买卖方向、市场成交量不均、窗口整分钟/非整分钟边界、
部分窗口持仓与费用、零成交/缺失分钟、缓存纠正、账户隔离、理论 NAV 与成本
结果一致性，以及原五分钟等量与全空回退规则。本地实现与验证不代表已部署。

本地验证：`cargo fmt --check`、`cargo check`、`cargo test`（402 passed、
20 ignored）、`cargo build --release` 全部通过。前端构建及 8 项成本分析测试通过，
lint 无错误，保留两项既有未使用变量警告和既有 bundle 大小提示。
