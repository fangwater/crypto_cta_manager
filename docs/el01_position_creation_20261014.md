# el01 普通用户创建仓位策略，2026-10-14

2026-10-15 更新：创建者的隐式配置权限已修复，创建者现在可以管理自己策略的
授权，并绑定到其有配置权限的账户。下面保留 10 月 14 日发布时的验证记录；
当时“创建不授予策略配置权限”的规则已被本次修复替代。

按操作员确认，所有已登录用户都可以创建仓位策略，不需要管理员角色或
单独的创建授权。el01 的 shaokai、dzy 已验证可创建并更新自己的私有策略，
两人的用户角色保持 `user`。创建时记录 `created_by_user_id`，默认不公开可见。
创建本身不授予账户绑定、策略授权管理或其他用户策略的更新权限。

匿名请求、失效会话、仅携带策略 token 或有效全局兜底 token 均不能创建
不存在的策略。已有策略继续按管理员、创建者、推送管理者、可配置授权、
策略 token 或兜底 token 鉴权；已有无 token 策略仍保留旧机器推送行为。
保存处理器在配置锁内读取和检查策略权限，两个普通用户同时创建同名策略时，
仅第一个请求成功，后一个请求返回 403，创建者不会被覆盖。

浏览器向普通用户显示“新建”，并使用策略目录返回的 `can_publish` 判断已保存
目标的编辑权限。创建者刷新后仍可编辑。手机策略表单使用显式单列网格，
修复新建页面验证时发现的 5 像素横向溢出。API 归档格式和 PostgreSQL
schema 未变化。
